# 学伴推荐智能体输入、流程与输出

实现位置：`backend/app/services/agents/study_buddy.py`。提示词位于 `backend/config/prompts/study_buddy.yaml`。

## 职责范围

学伴推荐智能体只处理“为学习者推荐共同学习伙伴”的请求，不承担闲聊、用户资料查询或知识讲解。非推荐请求直接返回边界说明和空学伴列表，不访问数据库或图模型。

推荐流程与资源推荐一致：

```text
LLM Plan
  -> SqlRetrievalTool（可选）
  -> RankingTool(personality 或 similarity)
  -> LLM Reflection
  -> LLM Summary
```

Plan 只允许 `SqlRetrievalTool` 和 `RankingTool`；排序只允许 `personality`、`similarity`。Reflection 读取计划和实际执行轨迹，未通过时使用建议重新规划，最多执行配置的反思轮数。

## 输入

| 字段 | 必填 | 说明 |
|---|---:|---|
| `user_id` | 是 | 当前学习者的数据库 ID，也是图模型 learner 节点 ID |
| `current_message` | 是 | 本轮学伴推荐请求 |
| `recent_messages` | 是 | 最近对话；仅在本轮没有明确检索目标时辅助 SQL 召回 |
| `topic` | 否 | 当前共同学习主题 |
| `diagnosis_result`、`user_profile` | 否 | 上游诊断与学习画像 |
| `weak_points`、`learning_style`、`current_level`、`grade_level` | 否 | 上游画像中的扁平字段 |

`current_message` 中明确指定的用户名、共同学习主题、年级、学习风格、水平、数量和范围优先于上游信息。用户明确给出多个用户名或主题时，SQL 必须分别匹配所有并列目标。

## SQL 召回

`SqlRetrievalTool` 仅执行单条只读 `SELECT`，并且必须返回 `users.id`（可别名为 `user_id`）。允许查询：

- `users`：只使用公开用户名和 `is_active`；禁止查询或返回 `email`、`hashed_password`。
- `user_profiles`：学习风格、当前水平、年级。
- `learner_knowledge_interactions` 与 `knowledge_points`：共同学习的学科、知识点和主题。

SQL 会检查语句、表和写操作关键字，并在只读 session 中执行。SQL 只负责召回 `u.is_active = true` 的活跃候选，不排除当前用户或已有学伴，也不得将 `current_user_id` 等占位文字写入 SQL；这两类过滤由后续 `RankingTool` 统一处理。SQL 缺失或无结果时，执行器在排序前加载全部活跃用户，并记录内部 `CandidateFallback` 轨迹。

## 排序

`RankingTool.input` 的形状如下：

```json
{"schema": "personality", "num": 5}
```

`num` 未指定或非法时默认 5，最大值为 15。用户在问题中明确要求数量时，Plan 必须把相同整数写入 `target_count` 和最终 `RankingTool.input.num`。

| schema | 行为 |
|---|---|
| `personality` | 在当前完整图上执行共享异构 GAT 前向，并使用学伴排序头为候选用户打分。 |
| `similarity` | 在当前完整图上执行共享异构 GAT 前向，计算当前学习者与每位候选的 learner 节点向量余弦相似度。 |

两种学伴排序都会过滤当前用户与 `learner_learner_relations` 中已有的学伴关系；未知数据库 ID 和重复 ID 也不会进入图模型。图模型不可用时保留候选原顺序并记录降级。

## 输出

顶层输出至少包含：

```json
{
  "recommendation_text": "面向学习者的学伴推荐说明",
  "buddies": [
    {
      "user_id": "学伴数据库 ID",
      "nickname": "公开用户名",
      "rank": 1,
      "graph_score": 0.82,
      "strengths": ["知识点"],
      "weaknesses": ["知识点"],
      "contact_suggestion": "联系建议",
      "collaboration_mode": "协作方式"
    }
  ],
  "planning": {"recall_strategy": "", "ranking_criteria": ["personality"], "target_count": 0},
  "matching_plan": {},
  "group_suggestion": {},
  "reflection": {"passed": true},
  "tool_trace": [],
  "plan_history": [],
  "reflection_history": []
}
```

相似度结果使用 `similarity_score`；为兼容现有下游，`complement_score` 会保留为归一化后的展示分数。`buddy_list` 是包含 `buddies`、`planning`、`rationale`、`sequence`、`tool_trace` 的下游兼容别名；文本输出也同时提供 `response_text`、`content`、`raw_response`、`final_response`。

正常推荐会写入 `buddy_recommendations`：`rec_partners` 保存最终学伴，`rec_ranks` 保存 `graph_score`、`similarity_score` 与展示分数。展示推荐结果不会新建 `learner_learner_relations`，因此不会将“被推荐”误作为已有学伴关系。

## 模型训练与启动

学伴排序头与资源排序头共享同一图模型。训练与后端使用 `.env` 中配置的同一个 checkpoint 目录；使用业务数据时从后端目录执行：

```bash
cd backend
alembic upgrade head
python algorithm/graph_recommender/train.py

# 训练完成后重启后端
uvicorn app.main:app --reload --port 8000
```

该命令会将 `encoder.pt`、`resource_scorer.pt`、`peer_scorer.pt` 与 `model_config.json` 写入 checkpoint 目录。学伴训练依赖 `learner_learner_relations` 的正例；资源交互、资源-知识点、学习者-知识点和知识点关系会共同增强共享图。文本 Embedding 始终缓存到数据库 `graph_node_embeddings`，不写入 checkpoint。

训练前需在 `.env` 中配置同一个 checkpoint 目录与文本模型：

```dotenv
SMART_TUTOR_GRAPH_RECOMMENDER__CHECKPOINT_DIR=algorithm/graph_recommender/ckpt
SMART_TUTOR_GRAPH_RECOMMENDER__EMBEDDING_MODEL_ID=BAAI/bge-small-zh-v1.5
```

详细的数据要求、训练切分、checkpoint 配置和在线同步方式见 [`backend/algorithm/graph_recommender/README.md`](../backend/algorithm/graph_recommender/README.md)。后续真实学伴关系写入 `learner_learner_relations` 后，应用 ORM 会在提交成功后自动同步图；外部写入方应按手册的 `GraphChange(relation_type="partnered_with", ...)` 示例，在提交后调用 `sync_after_commit(changes)`。

## 匿名演示接口

```text
POST /api/v1/agent-demos/study-buddy/run
```

接口不需要认证，不写推荐记录和执行日志。它要求测试学伴用户已初始化，用于验证 SQL、图排序和输出链路，而非评估推荐质量。
