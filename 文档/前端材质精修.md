## 修复 1：全局金色边框清除（最高优先级）

```
# 任务：清除滥用的金色描边，还原正确的边框层级

## 问题描述
当前所有容器（左栏会话列表项、右栏面板区块、中栏欢迎卡片、操作按钮边框）都使用了金色（--color-accent）作为 border-color，导致整体看起来像线框图/debug模式。

## 修复规则

### 应该使用 --color-border-subtle（#262A35 暗灰）的位置：
- 左栏每个会话列表项的外边框
- 右栏"智能体工作室"整体面板边框
- 右栏内各区块（Hero Slot 容器、Ensemble Rail 容器、Trace Timeline 容器）的分隔线
- 中栏思考过程面板的外边框
- 中栏对话输入框的边框（focus 态可以用金色，非 focus 态用 subtle）
- 顶部导航栏底部分隔线
- 所有区域之间的分隔线

### 唯一允许使用金色描边的位置（且必须是 1.5px 渐变描边）：
- 右栏 Hero Slot 里"本轮重点"agent 卡片（渐变：从上方 --color-accent 到下方 30% 透明）
- 中栏 Agent Interaction Log 中被标记为"本轮重点"的那一个 trace block

### 唯一允许使用金色填充/发光的位置：
- 左栏轨迹缩略图中标记为重点的圆点（且每条会话最多 1-2 个金点，不能全部都是金色）
- 中栏认知路径条中高亮/活跃节点
- "本轮重点"徽章文字和图标

## 执行方式
1. 全局搜索 border-color 或 border 属性中引用 --color-accent 的位置
2. 除了上面列出的"允许位置"外，全部替换为 --color-border-subtle
3. 搜索 box-shadow 中包含 accent 色的位置，除 Hero Slot 呼吸光晕外全部移除
4. 线宽统一：普通分隔线 0.5px，重点描边 1.5px，不允许其他值

## 硬约束
- 不允许存在两个以上容器同时显示金色描边（同一时刻画面上最多 1-2 处金色）
- 修改后整体界面应该是"深色底 + 几乎看不见的暗灰线条 + 极少数金色点睛"

## 验收 DoD
1. 截图整体界面：金色出现的位置不超过 3 处
2. 左栏会话列表项边框是暗灰色而非金色
3. 右栏面板容器边框是暗灰色而非金色
4. 只有"本轮重点"相关元素才有金色
```

## 修复 2：材质质感层补齐

```
# 任务：补齐 noise 材质层 + 卡片 inset 高光 + 方向性阴影

## 问题描述
当前界面是纯平面色块，缺乏设计文档要求的"物理质感"三层：
- 底层 noise 纹理
- 卡片顶部 1px inset 高光
- 层级阴影系统

## 输出契约

### 1. Noise 材质层
在全局样式中添加 body::before 伪元素：

```css
body::before {
  content: '';
  position: fixed;
  inset: 0;
  z-index: 9999;
  pointer-events: none;
  opacity: 0.04; /* Light 主题下用 0.025 */
  background-image: url("data:image/svg+xml,%3Csvg viewBox='0 0 256 256' xmlns='http://www.w3.org/2000/svg'%3E%3Cfilter id='noise'%3E%3CfeTurbulence type='fractalNoise' baseFrequency='0.9' numOctaves='4' stitchTiles='stitch'/%3E%3C/filter%3E%3Crect width='100%25' height='100%25' filter='url(%23noise)'/%3E%3C/svg%3E");
  background-repeat: repeat;
  background-size: 256px 256px;
}
```

### 2. 卡片 Inset 高光
所有 elevated 层级的容器（右栏面板、思考过程面板、Hero Slot 卡片），在 box-shadow 中加入 inset 高光：

```css
/* elevation-2 级（普通面板） */
box-shadow: 0 1px 2px rgba(0,0,0,0.06), inset 0 1px 0 rgba(255,255,255,0.04);

/* elevation-3 级（Hero Slot 卡片、重点面板） */
box-shadow: 0 8px 24px -8px rgba(0,0,0,0.15), inset 0 1px 0 rgba(255,255,255,0.06);
```

关键：`inset 0 1px 0 rgba(255,255,255,0.04)` 是模拟"光从顶部来"的物理感，肉眼看是卡片顶边有一条极细的白色高光。

### 3. 方向性阴影
当前的 box-shadow 如果只有均匀扩散，需要改为向下偏移：
- 阴影向下偏移（y > 0），不允许上下均匀扩散
- 模糊半径要大于偏移量（显得柔和而非硬边）
- 颜色只用 rgba(0,0,0,x)，禁止彩色阴影

## 硬约束
- noise 层 opacity 不允许超过 0.05（否则视觉脏）
- inset 高光颜色只允许 rgba(255,255,255,0.04~0.08)，不允许用金色
- 阴影颜色只允许黑色系 rgba(0,0,0,x)，禁止用 accent 色
- Light 主题下阴影 rgba 数值略微调高（0.06 → 0.08）即可，不需要换色相

## 验收 DoD
1. 关掉 noise 层（opacity 设为 0）前后截图对比：能感知到"有质感 vs 塑料感"差异
2. 用 Devtools 检查 Hero Slot 卡片：能看到 inset 0 1px 高光
3. 全部 box-shadow 都是向下偏移、黑色系、无彩色
```

## 修复 3：字体系统生效

```
# 任务：引入 Inter + JetBrains Mono 字体并建立层级

## 问题描述
当前使用默认系统字体，没有设计文档要求的字体系统。字体是区分"高级感"和"普通感"最有效的单一因素。

## 输出契约

### 1. 引入字体
在 index.html 的 <head> 中添加（或在全局 CSS 中 @import）：

```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700&family=JetBrains+Mono:wght@400;500&display=swap" rel="stylesheet">
```

### 2. 全局字体设置
```css
:root {
  --font-display: 'Inter', -apple-system, BlinkMacSystemFont, system-ui, sans-serif;
  --font-body: 'Inter', -apple-system, BlinkMacSystemFont, system-ui, sans-serif;
  --font-mono: 'JetBrains Mono', ui-monospace, SFMono-Regular, Menlo, monospace;
}

body {
  font-family: var(--font-body);
  font-feature-settings: 'ss01', 'cv11';
  font-variant-numeric: tabular-nums;
  -webkit-font-smoothing: antialiased;
  -moz-osx-font-smoothing: grayscale;
}
```

### 3. 字体层级使用规则
| 位置 | 字体 | 字号 | 字重 | 字距 |
|------|------|------|------|------|
| 右栏 Agent 名称（Hero Slot 标题） | var(--font-display) | 18px | 600 | -0.02em |
| 左栏会话主题 | var(--font-body) | 13px | 500 | -0.01em |
| 正文/对话内容 | var(--font-body) | 14px | 400 | -0.01em |
| 思考过程字段名（DECISION 等） | var(--font-mono) | 12px | 500 | 0 |
| 思考过程字段值、参数值 | var(--font-mono) | 12px | 400 | 0 |
| 时间戳 | var(--font-mono) | 11px | 400 | 0.01em |
| 区块标题（"思考过程""智能体工作室"） | var(--font-body) | 12px | 500 | 0.04em |
| 数字（Token数、温度值等） | var(--font-mono) | — | — | — |

### 4. 字号阶梯硬约束
只允许使用：11 / 12 / 13 / 14 / 16 / 18 / 24 / 32 px
禁止出现非阶梯值（如 15px、17px、20px）。

## 硬约束
- 禁止引入 Inter / JetBrains Mono 之外的字体
- 所有数字（Token 数、温度值、时间戳、阶段数）必须用 var(--font-mono)
- 字重只允许 400 / 500 / 600 / 700，禁止 300 和 800+
- body 正文字距 -0.01em，标题 -0.02em，小字/标签 +0.01em ~ +0.04em

## 验收 DoD
1. 打开 Devtools → Computed → font-family：body 级别显示 Inter
2. 时间戳和参数值显示 JetBrains Mono
3. 全站无非阶梯字号
```

# 任务：给右栏"智能体工作室"添加有意义的空状态展示

当前用户发送消息前，右栏三个区块全部显示"等待 agent 调用..."，大面积空白。

## 硬约束
- 空状态不使用金色（因为没有"重点"）
- 空状态不使用动画（避免空转焦虑感）

## 修复 5：思考过程面板视觉升级

```
# 任务：把思考过程面板从"文字日志"升级为"可视化 Agent 交接流"

## 问题描述
当前思考过程面板虽然信息完整（显示 DECISION、NEXT_AGENTS、WORKFLOW_TYPE），
但视觉形态仍然是纯文字列表，缺乏"多 agent 协作"的可视化感知。

## 输出契约

### 每个 Agent 输出块的结构改为：
```
┌ [Avatar 圆形] ─── Agent 名称 ─── 状态标签 ────┐
│                                                    │
│  字段信息（grid 排布）                              │
│  Decision: xxx    Next: xxx    Workflow: xxx       │
│                                                    │
│  [如果是本轮重点] ⚡ 本轮重点（徽章）               │
└────────────────────────────────────────────────────┘
         │
    0.5px 竖线
         │
┌ [Avatar 圆形] ─── 下一个 Agent ──────────────────┐
```

### Avatar 圆形
- 24×24px 圆形
- 背景 --color-bg-elevated
- 边框 0.5px --color-border-subtle
- 内容：agent 名第一个字（如"决""知""共"）
- 字号 10px，字重 600，颜色 --color-text-secondary

### 竖线连接
- 从上一个 avatar 圆心到下一个 avatar 圆心
- 0.5px 实线，颜色 --color-border-subtle
- 位置：距离左边 12px（avatar 中心）

### 重点 Agent 块的差异化
- 整个内容区域加 1.5px 渐变描边（上方 --color-accent → 下方 transparent 30%）
- 描边用 border-image 或伪元素实现
- 底部多一行：Sparkles 图标（用 Lucide 或 SVG ✦）+ 文字"本轮重点"
- 图标和文字颜色 --color-accent
- 字号 11px

### 字段排布优化
- 使用 CSS Grid 两列排布：
  - 左列是 label（颜色 --color-text-tertiary，字号 11px）
  - 右列是 value（颜色 --color-text-primary，字号 12px，font-family: var(--font-mono)）
- 字段之间间距 4px
- 不再使用全大写英文字段名（如 DECISION），改为中文或首字母大写短标签

### "正在运行 xxx"进度指示
- 保留底部进度条
- 进度条高度 2px，颜色 --color-accent
- 进度条上方的文字"正在运行 xxx"前面加一个 8px 呼吸动画圆点

## 硬约束
- 不改变面板的折叠/展开交互逻辑
- 不改变面板出现的位置和触发条件
- 不改变信息内容（只改展示形式）
- avatar 内不使用 emoji，只用文字缩写

## 验收 DoD
1. 有重点标记的 Agent 块与普通块有明显视觉区别
2. Agent 块之间有竖线连接，形成"流"的感觉
3. 每个块左侧都有圆形 avatar
4. 全面板无金色边框（只有重点块有金色渐变描边）
```

## 修复 6：左栏轨迹缩略图差异化

```
# 任务：让左栏会话列表的学习轨迹圆点具有数据差异性

## 问题描述
当前每条会话的轨迹圆点数量和金色高亮位置看起来都差不多，
失去了"不同会话有不同学习深度"的信息传达。

## 修复规则

### 圆点数量应有差异
- 短对话（1-2 轮）：3-4 个圆点
- 中等对话（3-5 轮）：5-6 个圆点
- 长对话（6+ 轮）：7-8 个圆点（超过 8 个则省略中间，保留首尾）

### 金色高亮圆点的约束
- 每条会话最多 1-2 个金色圆点（代表该次会话中触及的重点知识节点）
- 大部分会话可以没有金色圆点（代表常规对话，没有特别重点）
- 金色圆点位置应该分散，不要都在同一位置

### 当前的 mock 数据建议
如果后端还没接上 nodes 字段，mock 数据要体现差异：
- 第 1 条："开始诊断" → 6 个点，第 2、5 位金色
- 第 2 条："新对话"（较早）→ 4 个点，第 3 位金色
- 第 3 条："新对话"（更早）→ 3 个点，无金色
- 第 4 条："新对话" → 5 个点，第 1 位金色
- ...以此类推，让列表有视觉节奏感

### 连接线
- 圆点之间用 0.5px 虚线连接（dasharray: 2 2）
- 虚线颜色 --color-border-subtle
- 不是金色

## 硬约束
- 会话列表项外边框不使用金色（用 --color-border-subtle 或无边框）
- 激活态会话项用背景色提亮（--color-bg-elevated）区分，不用金色边框
- 轨迹缩略图整体高度不超过 12px

## 验收 DoD
1. 肉眼扫一遍左栏：能看出不同会话的"学习深度"差异
2. 不是所有会话都有金色圆点
3. 会话列表项之间没有金色边框
```

> 把屏幕截图缩小到手机屏幕大小（模拟审查人远距离看投影）。
