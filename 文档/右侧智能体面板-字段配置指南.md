# 右侧智能体面板 — 字段配置指南

面向集成 Agent 的负责人。本文以 `cognitive_diagnosis`、`resource_recommender` 和 `study_buddy` 为例，说明如何修改 `AGENT_HIGHLIGHT_FIELDS`，将后端 output 中已有的字段展示到右侧面板。

---

## 1. 右侧那栏是干什么的

主对话页右栏（`MainLayout` 的 `w-80` 列）由三个组件层叠构成：

```
AgentInfoPanel (relative 容器, rightPanelOpen 控制)
  ├── AgentStudio (默认展示, 三段式)
  │     ├── Hero Slot (40%)      —— 本轮 focus agent 大卡片,最多 2 个
  │     ├── Ensemble Rail (40%)  —— 其他协作 agent 小卡片
  │     └── Trace Timeline (20%) —— agent 调用时间线
  │
  └── AgentDetailDrawer (浮层, 点任意卡片时 absolute inset-0 覆盖)
        ├── 段 1: 本轮输出      ← 你要改的就是这一段
        ├── 段 2: LLM 配置      (静态,从 AGENT_CONFIGS 来)
        ├── 段 3: Prompt 摘要   (静态)
        └── 段 4: Thinking Process (静态,标注"参考流程,非实时")
```

**用户路径**：对话过程中 → 右栏 Hero/Ensemble 卡片自动显示本轮 focus agent → 点卡片 → 弹出 AgentDetailDrawer → 段 1「本轮输出」展示这个 agent **真实跑出来的数据**。

**段 1 是唯一动态的部分**，也是这份文档要讲的核心。其它三段都是静态元数据，从 `AGENT_CONFIGS` 读，改那个文件即可。

## 2. 数据是怎么流到前端的

```
后端 agent.execute() 返回 {output: {...}}
          │
          ▼
stage_executor / agent_node 节点 push SSE thinking 事件
  → content = JSON.stringify(output)     ← 完整 output 序列化成字符串
          │
          ▼
前端 chat.service.ts onThinking(content, step, label)
          │
          ▼
chatStore.completeRunningStep(content, step, label)
  → agentTrace[agentName] = {content: string, label, updatedAt}
          │
          ▼
AgentDetailDrawer:
  parsedOutput = JSON.parse(agentTrace[name].content)
  → 用 AGENT_HIGHLIGHT_FIELDS[name] 声明的字段去 parsedOutput 里取值
  → 用 format 函数渲染成短字符串
```

**关键约束**：
- `agentTrace[name].content` 是**字符串**，前端靠 `JSON.parse` 二次解析
- 字段名必须和你 agent 的 output 顶层 key **完全一致**（或用点路径取嵌套字段）
- 想展示什么数据，必须保证该数据**真的在你的 agent output 里**

## 3. AGENT_HIGHLIGHT_FIELDS 模板

位置：`frontend/src/data/agentConfigs.ts` 文件底部（约 line 388）。

```ts
export interface HighlightFieldDef {
  key: string;                              // 字段路径(支持 'a.b.c' 点路径)
  label: string;                            // 中文标签,显示在字段上方
  format?: (v: unknown) => string;          // 可选,把原始值转成短字符串
}

export const AGENT_HIGHLIGHT_FIELDS: Record<string, HighlightFieldDef[]> = {
  cognitive_diagnosis: [...],     // ← 知识追踪负责人改这里
  resource_recommender: [...],    // ← 资源推荐负责人改这里
  study_buddy: [...],             // ← 学伴推荐负责人改这里
};
```

**最小修改单元**（加一个展示字段）：

```ts
cognitive_diagnosis: [
  // ...已有字段
  { key: 'your_new_field', label: '你的字段' },      // 无 format,直接 String()
],
```

**带格式化**：

```ts
{
  key: 'mastery_rates',
  label: '掌握度',
  format: (v: unknown) => {
    if (typeof v !== 'object' || v === null) return '-';
    const entries = Object.entries(v as Record<string, number>).slice(0, 3);
    return entries.map(([k, val]) => `${k}: ${(val * 100).toFixed(0)}%`).join(' / ') || '-';
  },
},
```

cognitive_diagnosis: [
  { key: 'diagnosis_source',  label: '数据来源',    format: ... },  // 区分 kt_reekt / LLM模拟
  { key: 'weak_points',       label: '薄弱点',      format: ... },  // 兼容 dict[] 和 string[]
  { key: 'knowledge_states',  label: '知识点',      format: ... },  // 数量
  { key: 'diagnosis_summary', label: '诊断总结',    format: ... },  // 截断 60 字
  { key: 'mastery_rates',     label: '掌握度',      format: ... },  // 前 3 项 key: NN%

### 4.2 `resource_recommender`（资源推荐）

```ts
resource_recommender: [
  { key: 'resources',                   label: '推荐资源',  format: ... },  // 前 2 个 title + 总数
  { key: 'recommendation_text',         label: '推荐语',    format: ... },  // 截断 40 字
  { key: 'resources.0.graph_score',     label: '图模型分数', format: ... }, // toFixed(4)
  { key: 'planning.recall_strategy',    label: '召回策略',  format: ... },
  { key: 'planning.target_count',       label: '目标数',    format: ... },
  { key: 'reflection.coverage_score',   label: '覆盖度',    format: ... },  // 百分比
  { key: 'reflection.passed',           label: '反思通过',  format: ... },  // 是/否
  { key: 'tool_trace',                  label: '工具轨迹',  format: ... },  // N 步
  { key: 'plan_history',                label: '规划轮数',  format: ... },  // N 轮
  { key: 'reflection_history',          label: '反思轮数',  format: ... },  // N 轮
],
```

对应后端 output（`backend/app/services/agents/resource_recommender.py:_ensure_output_shape`）的关键字段：

| 字段 | 类型 | 来源 | 说明 |
|---|---|---|---|
| `recommendation_text` | `string` | LLM summary | 自然语言推荐语 |
| `resources` | `list[dict]` | SQL 候选 + 图排序 + LLM 文案整理 | 每项含 `id / title / type / url / difficulty / time_needed_min / knowledge_tags / recommend_reason / rank / graph_score? / similarity_score?`；相似度项还含锚点 ID 与标题 |
| `planning` | `dict` | LLM plan | `recall_strategy / ranking_criteria / target_count` |
| `reflection` | `dict` | LLM reflection | `coverage_score / difficulty_match / diversity_score / passed / improvement_suggestion` |
| `tool_trace` | `list[dict]` | 工具执行 | SQL、排序和可能的 `CandidateFallback`；排序项含实际 schema、数量策略、候选来源和排序后端 |
| `plan_history` | `list[dict]` | 循环累积 | **plan 阶段每一轮的 LLM 输出**（含 thought / tool_calls / target_knowledge） |
| `reflection_history` | `list[dict]` | 循环累积 | **reflection 阶段每一轮**（含 passed / issues / suggestion / scores） |
| `rationale` | `string` | LLM summary | 推荐理由 |
| `sequence` | `list` | LLM summary | 推荐顺序 |

### 4.3 `study_buddy`（学伴推荐）

当前前端默认展示候选学伴和推荐语；可按同一方式追加图分数、相似度分数、目标数量或工具轨迹：

```ts
study_buddy: [
  { key: 'buddies',                 label: '候选学伴',   format: ... },
  { key: 'recommendation_text',     label: '推荐语',     format: ... },
  { key: 'buddies.0.graph_score',   label: '图模型分数', format: ... },
  { key: 'buddies.0.similarity_score', label: '相似度',  format: ... },
  { key: 'planning.target_count',   label: '目标数',     format: ... },
]
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `buddies` | `list[dict]` | 每项含 `user_id / nickname / rank / graph_score? / similarity_score? / complement_score / strengths / weaknesses / contact_suggestion / collaboration_mode` |
| `planning` | `dict` | `recall_strategy / ranking_criteria / target_count` |
| `matching_plan`、`group_suggestion` | `dict` | 下游兼容的协作建议字段 |
| `reflection`、`tool_trace`、`plan_history`、`reflection_history` | 与资源推荐同义 | 记录本轮计划、执行和反思过程 |

> **重点**：`plan_history / reflection_history` 由两个推荐智能体在输出组装时写入顶层 output。需要展示任何中间过程时，先确认该字段已经在 output 中，再在 `AGENT_HIGHLIGHT_FIELDS` 使用同名字段或点路径。

## 5. 我想展示一个新字段，怎么办？

### 情况 A：字段已经在 agent output 里

直接改 `AGENT_HIGHLIGHT_FIELDS`，加一条 `{key, label, format?}`。

例子：你想展示 `cognitive_diagnosis` 的 `topic_analysis`：

```ts
cognitive_diagnosis: [
  // ...已有
  {
    key: 'topic_analysis',
    label: '主题分析',
    format: (v: unknown) => typeof v === 'string' ? (v.length > 80 ? `${v.slice(0, 80)}…` : v) : '-',
  },
],
```

### 情况 B：字段在嵌套结构里

用点路径。`getValueByPath` 支持任意层级嵌套和数组下标。

例子：取第一个资源的学习建议：

```ts
{ key: 'resources.0.recommend_reason', label: '推荐理由', format: ... }
```

取认知归因的第一个根本原因：

```ts
{ key: 'cognitive_attribution.root_causes.0', label: '主因', format: ... }
```

### 情况 C：字段还没在 output 里（过程数据 / 中间步骤）

这是最常见的情况。比如你想展示：
- KT 模型推理时的输入参数（targets、initial_query）
- LLM plan 阶段原始的 thought（未结构化的）
- 工具调用的中间结果（不只是 tool_trace 摘要）

**两步走**：

**第一步（后端）**：在你的 agent `execute()` 里，把这个数据塞进 `output` dict。位置：
- `cognitive_diagnosis`：`backend/app/services/agents/cognitive_diagnosis.py` 的 `_merge_kt_with_llm` 或 `super().execute()` 之后
- `resource_recommender`：`backend/app/services/agents/resource_recommender.py` 的 `_summary` 方法

参考 `resource_recommender._summary` 是怎么做的（约 line 205-207）：

```python
def _summary(self, ..., plan_history, reflection_history):
    payload = { ...原本的字段... }
    # 加你要展示的过程数据
    payload["plan_history"] = plan_history
    payload["reflection_history"] = reflection_history
    return payload
```

如果用 `_ensure_output_shape` 之类的白名单 schema 校验，记得把新字段加进白名单（参考 `resource_recommender.py:_ensure_output_shape`）。

**第二步（前端）**：在 `AGENT_HIGHLIGHT_FIELDS[你的agent]` 加字段。

> 注意：output 是会被 SSE 序列化、JSON.parse、显示的。**别塞太大的字段**（比如完整 dataset），单字段建议 < 10KB。大对象请先在 agent 里裁剪或摘要。

## 6. format 函数怎么写

`format?: (v: unknown) => string`，把后端原始值转成短字符串。**不传则默认 `String(v)`**。

**约定**：
- 任何意外类型都返回 `'-'`，不要抛异常
- 字符串过长（> 40-60 字）截断加 `…`
- 数组展示数量（`${v.length} 个`）或前 2-3 项
- 对象展示前几个 key-value

**常用模板**：

```ts
// 数字百分比
format: (v) => typeof v === 'number' ? `${(v * 100).toFixed(0)}%` : '-'

// 数字保留 4 位
format: (v) => typeof v === 'number' ? v.toFixed(4) : '-'

// 布尔转中文
format: (v) => v === true ? '是' : v === false ? '否' : '-'

// 字符串截断
format: (v) => typeof v === 'string' ? (v.length > 40 ? `${v.slice(0, 40)}…` : v) : '-'

// 数组数量
format: (v) => Array.isArray(v) ? `${v.length} 个` : '-'

// 数组取前 N 项 name
format: (v) => {
  if (!Array.isArray(v)) return '-';
  const names = v.slice(0, 2).map(item =>
    typeof item === 'object' && item !== null
      ? (item.title || item.name || item.skill_id || '未命名')
      : String(item)
  );
  return names.length > 0 ? `${names.join('、')} (${v.length} 个)` : '-';
}

// 枚举映射
format: (v) => v === 'kt_reekt' ? '真实KT模型' : 'LLM模拟'
```

## 7. 想展示「思考过程」（非最终结果）

目前两种做法：

### 做法 1（保守，已落地）：过程数据塞进 output

参考 `resource_recommender` 的 `plan_history / reflection_history`。优点是改动小（只动 agent），缺点是**等 agent 跑完才能看到**，不是实时。

### 做法 2（未来扩展）：实时 SSE 子事件

让 agent 在执行过程中主动 push SSE 事件（plan 阶段一次、每个 tool 一次、reflection 一次）。需要改：
- `BaseAgent.execute` 签名加 `step_queue` 参数
- `stage_executor.py` 把 step_queue 传进 agent
- agent 各阶段末尾 `await step_queue.put({"type": "thinking", "subtype": "plan", ...})`
- 前端 `chatStore` 加 `appendAgentSubstep` action
- 前端 `AgentInteractionLog` 按 subtype 渲染子卡片

侵入性较大，本轮没做。如果确实需要实时性，可以单独立项。

## 8. 验证清单

改完 `AGENT_HIGHLIGHT_FIELDS` 后：

1. **TypeScript 类型检查**：
   ```bash
   cd frontend && npx tsc --noEmit
   ```
   必须零错误。

2. **本地起前端 dev server**：
   ```bash
   cd frontend && npm run dev
   ```
   浏览器打开对话页，发一句话触发 agent 执行，点右栏卡片看抽屉。

3. **检查字段对齐**：
   - 抽屉段 1「本轮输出」每个字段都应该有值，不应该全是 `-`
   - 如果全是 `-`，说明 `key` 拼错了，或后端 output 没这个字段
   - 打开浏览器 DevTools Console，输入：
     ```js
     useChatStore.getState().agentTrace['你的agent名']?.content
     ```
     看实际 JSON 字段名

4. **`extraFields` 兜底**：被 highlightFields 覆盖的顶层字段不会出现在底部 extraFields。如果你看到 extraFields 里冒出你想展示的字段，说明 `key` 没配对。

## 9. 常见问题

**Q: 我加了字段，前端显示全是 `-`。**
A: 三种可能：
1. `key` 拼错（注意大小写、下划线 vs 驼峰）
2. 字段不在 output 里（情况 C，先改后端）
3. format 函数判断条件太严（比如 `typeof v === 'number'` 但后端给的是字符串数字）

**Q: 我想加的字段在 SSE done 事件里，不在 thinking 里。**
A: done 事件目前只透出 KT 聚合字段（`touchedNodes / ktSummary / focusAgents / trajectory`），不走 `agentTrace`。AgentDetailDrawer 段 1 只读 `agentTrace`。如果你要展示 done 字段，需要另开组件（如 `CognitivePathBar`），不在本指南范围。

**Q: 我的字段在 output 里是嵌套很深的对象。**
A: 用点路径，比如 `cognitive_attribution.root_causes.0.category`。`getValueByPath` 支持任意深度。但展示效果会很扁（一个 grid cell 显示一个值），如果对象太大建议在 agent 里先 summary 成字符串。

**Q: 我想动态决定展示哪些字段（比如 KT 模式 vs LLM 模式不同字段）。**
A: `AGENT_HIGHLIGHT_FIELDS` 是静态的，运行时不支持条件字段。两种做法：
1. 把所有可能字段都配上，format 里判断（比如 KT 模式才显示数据来源）
2. 改 `AgentDetailDrawer.tsx` 在渲染前按 `parsedOutput.diagnosis_source` 过滤字段（侵入性较大）

**Q: 我想加新的 agent。**
A: 在 `AGENT_CONFIGS` 里加完整元数据，在 `AGENT_DISPLAY_ORDER` 加名字，在 `AGENT_HIGHLIGHT_FIELDS` 加字段配置。三处都要改。
