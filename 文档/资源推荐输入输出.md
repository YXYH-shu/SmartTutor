# 资源推荐智能体输入、流程与输出

实现位置：`backend/app/services/agents/resource_recommender.py`。提示词位于 `backend/config/prompts/resource_recommender.yaml`。

## 职责范围

资源推荐智能体只处理学习资源推荐，不承担闲聊、资源库信息查询或知识讲解。非推荐请求直接返回边界说明和空资源列表，不访问数据库或图模型。

推荐请求按以下固定流程运行：

```text
LLM Plan
  -> SqlRetrievalTool（可选）
  -> RankingTool(personality 或 similarity)
  -> LLM Reflection
  -> LLM Summary
```

Plan 只允许 `SqlRetrievalTool` 和 `RankingTool`；排序只允许 `personality`、`similarity`。Reflection 能看到 Plan、SQL 结果、候选来源、数量策略、实际排序类型和最终结果。未通过时会带着建议再次规划，最多执行配置的反思轮数。

## 输入

| 字段 | 必填 | 说明 |
|---|---:|---|
| `user_id` | 是 | 当前学习者的数据库 ID，也是图模型 learner 节点 ID |
| `current_message` | 是 | 本轮自然语言推荐请求 |
| `recent_messages` | 是 | 最近对话列表；仅在当前问题没有明确检索目标时辅助 SQL 召回 |
| `diagnosis_result` | 否 | 上游认知诊断结果 |
| `user_profile` | 否 | 上游学习画像 |
| `target_knowledge` | 否 | 上游目标知识点 |
| `learning_style`、`difficulty` | 否 | 上游学习偏好与难度信息 |

本轮 `current_message` 中明确给出的资源标题/ID、学科、知识点、类型、数量或范围优先于上游信息。例如“从 A、B、C 中选一个”只召回 A、B、C；“推荐两个物理资源”以知识点表的学科字段作为主条件。

## SQL 召回

`SqlRetrievalTool` 仅执行单条只读 `SELECT`，并且必须返回 `learning_resources.id`。允许查询：

- `learning_resources`：资源标题、内容、类型、难度、学习时长。
- `resource_knowledge`：资源与知识点的关联。
- `knowledge_points`：知识点名称、内容、学科、年级、课程标准。

SQL 会校验单语句、`SELECT` 开头、表白名单与写操作关键字，并通过数据库只读 session 执行。对资源正文搜索时使用 `LEFT JOIN`，避免遗漏未关联知识点的资源；多对多关联使用 `SELECT DISTINCT lr.id` 去重。

当 Plan 没有调用 SQL，或 SQL 结果为空时，执行器会在排序前加载 `learning_resources` 全集，并在 `tool_trace` 写入内部 `CandidateFallback` 记录。该记录不是 LLM 可以规划的工具。

## 排序

`RankingTool.input` 的形状如下：

```json
{"schema": "personality", "num": 5}
```

`num` 未指定或非法时默认 5，最大值为 15。用户在问题中明确要求数量时，Plan 必须同时写入 `target_count` 和最终 `RankingTool.input.num`；执行轨迹会记录原始数量、实际数量和裁剪原因。

| schema | 行为 |
|---|---|
| `personality` | 对候选资源执行共享异构 GAT 的全图前向，再通过资源排序头打分。图模型不可用时保持候选原顺序并记录降级。已有资源交互不会过滤资源，允许重复学习。 |
| `similarity` | SQL 召回资源锚点；以冻结文本 Embedding 分别计算每个锚点与全部非锚点资源的余弦相似度。多锚点分数不聚合，同一资源可因不同锚点重复出现。若没有有效锚点，改用全部资源执行 `personality`。 |

资源相似度的文本向量从 `graph_node_embeddings` 读取，不会因图边数量增加而增加相似度计算成本；个性化排序会使用请求时的完整图。

## 输出

顶层输出至少包含：

```json
{
  "recommendation_text": "面向学习者的推荐说明",
  "resources": [
    {
      "id": "资源数据库 ID",
      "title": "资源标题",
      "type": "video/article/quiz/practice",
      "url": "资源链接",
      "difficulty": "难度标签",
      "time_needed_min": 20,
      "knowledge_tags": ["知识点"],
      "recommend_reason": "推荐原因",
      "rank": 1,
      "graph_score": 0.82
    }
  ],
  "planning": {"recall_strategy": "", "ranking_criteria": ["personality"], "target_count": 0},
  "reflection": {"passed": true},
  "tool_trace": [],
  "plan_history": [],
  "reflection_history": []
}
```

相似度结果不含 `graph_score`，而包含 `similarity_score`、`similarity_reference_id`、`similarity_reference_title`。`resource_list` 是包含 `resources`、`planning`、`rationale`、`sequence`、`tool_trace` 的下游兼容别名；`response_text`、`content`、`raw_response`、`final_response` 均是推荐文本别名。

正常推荐会写入 `resource_recommendations`，其中 `rec_resources` 保存最终资源，`rec_ranks` 保存 `graph_score` 或相似度锚点信息；展示推荐结果本身不会创建 `learner_resource_interactions`，因此不会把展示误认为真实学习行为。

## 模型训练与启动

资源排序头与学伴排序头共用一个图模型。训练与后端从 `.env` 配置的 checkpoint 目录读取和写入同一组文件：

```bash
cd backend
alembic upgrade head
python algorithm/graph_recommender/train.py

# 训练完成后重启后端
uvicorn app.main:app --reload --port 8000
```

训练会将 `encoder.pt`、`resource_scorer.pt`、`peer_scorer.pt` 与 `model_config.json` 写入该目录。训练前请在 `.env` 中确认：

```dotenv
SMART_TUTOR_GRAPH_RECOMMENDER__CHECKPOINT_DIR=algorithm/graph_recommender/ckpt
SMART_TUTOR_GRAPH_RECOMMENDER__EMBEDDING_MODEL_ID=BAAI/bge-small-zh-v1.5
```

详细的数据要求、训练切分、checkpoint 配置和在线同步方式见 [`backend/algorithm/graph_recommender/README.md`](../backend/algorithm/graph_recommender/README.md)。后续真实学习交互写入 `learner_resource_interactions` 后，应用 ORM 会在提交成功后自动同步图；外部写入方应按手册的 `GraphChange(relation_type="interacted_with", ...)` 示例，在提交后调用 `sync_after_commit(changes)`。
