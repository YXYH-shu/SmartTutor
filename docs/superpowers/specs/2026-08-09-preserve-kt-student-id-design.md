# 保留 KT 学生 ID 的最小修改设计

## 目标

当用户原始消息包含“学生42”或 `student 42` 时，即使安全链路随后改写消息并删除编号，认知诊断仍应收到 `kt_student_id="42"`，避免回退到演示学生 43。

## 范围

只修改安全节点的共享上下文写入逻辑，不增加权限校验，不修改安全提示词、`TutorState` 结构、阶段调度器或 KT 解析器。

## 数据流

安全节点在调用安全模型前，从最后一条原始用户消息中提取 `学生/Student + 数字`。匹配成功时写入 `state.context["kt_student_id"]`；未匹配时不写入，也不覆盖已有值。安全模型仍可正常改写消息。后续 `stage_executor` 会把共享 `context` 展开到智能体输入，现有 `resolve_kt_student_id()` 会优先读取该字段。

## 测试

- 原始消息为“对学生42做认知诊断”时，共享上下文保留 `kt_student_id="42"`。
- 原始消息为英文 `student #42` 时同样保留 `42`。
- 普通消息不新增 `kt_student_id`。
- 安全模型返回 TRANSFORM 后，保存的 ID 仍存在于节点输出的 `context` 中。

## 非目标

本次不解决教师权限校验、自然语言中任意数字 ID 的授权问题，也不处理认知诊断成功后仍调用 LLM 的问题。
