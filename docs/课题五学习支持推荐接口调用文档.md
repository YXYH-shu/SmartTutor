# 学习支持推荐接口调用文档

## 1. 概述

本文档说明课题五调用学习资源推荐和学习伙伴推荐能力的方式。

接口通过同一个入口提供两种场景：

| 场景 | `scenarioCode` | 返回内容 |
| --- | --- | --- |
| 学习资源推荐 | `resourceRecommendation` | `data.recommendations` 中的资源 ID 和推荐理由 |
| 学习伙伴推荐 | `studyBuddyRecommendation` | `data.ext.studyBuddyRecommendation.buddies` 中的学伴信息 |

接口使用同步 HTTP `POST` 请求，所有业务结果均使用统一 JSON 信封返回。调用方应以响应体中的 `code` 判断处理结果，不应只依据 HTTP 状态码判断成功或失败。

## 2. 接口地址

```text
POST {服务地址}/internal/v1/processTutoringInteraction
```

例如本机联调地址：

```text
http://127.0.0.1:8000/internal/v1/processTutoringInteraction
```

## 3. 请求头

| 请求头 | 必选 | 类型 | 说明 |
| --- | --- | --- | --- |
| `appId` | 是 | string | 调用方应用标识。|
| `userId` | 是 | string | 当前学习者的用户 ID。应传入已在服务侧可识别的学习者 ID。|
| `requestId` | 是 | string | 本次调用的唯一请求标识。建议使用 UUID，响应会原样返回。|
| `apiVersion` | 是 | string | 固定为 `v1`。|
| `userRole` | 否 | string | 调用方用户角色扩展字段。当前版本不要求传入。|
| `Content-Type` | 是 | string | 固定为 `application/json; charset=utf-8`。|

## 4. 请求体

### 4.1 顶层结构

```json
{
  "processingStage": "learningSupport",
  "data": {
    "scenarioCode": "resourceRecommendation",
    "interactionContext": {},
    "userContext": {},
    "learningEvidence": []
  },
  "ext": {}
}
```

| 字段 | 必选 | 类型 | 说明 |
| --- | --- | --- | --- |
| `processingStage` | 是 | string | 固定为 `learningSupport`。|
| `data` | 是 | object | 学习支持推荐的请求数据。|
| `ext` | 否 | object | 调用方扩展信息。当前版本允许传入未知扩展字段。|

### 4.2 `data` 公共字段

| 字段 | 必选 | 类型 | 说明 |
| --- | --- | --- | --- |
| `scenarioCode` | 是 | string | `resourceRecommendation` 或 `studyBuddyRecommendation`。|
| `interactionContext` | 否 | object | 当前问题、多轮对话和已交互对象。建议始终传入。|
| `userContext` | 是 | object | 学习者的基础学习上下文。|
| `learningEvidence` | 是 | array | 至少一条当前学习证据。|
| `candidateResources` | 否 | array | 仅资源推荐使用的候选资源列表。非空时结果只在此列表内排序。|
| `candidateUsers` | 否 | array | 仅学伴推荐使用的候选用户列表。非空时结果只在此列表内排序。|

### 4.3 `interactionContext`

```json
{
  "query": "请推荐两个适合复习牛顿运动定律的资源",
  "draftAnswer": "可以先从受力分析开始复习。",
  "history": [
    {
      "role": "user",
      "content": "我对牛顿第二定律不太熟悉。"
    },
    {
      "role": "assistant",
      "content": "你可以先练习受力分析。"
    },
    {
      "resourceId": "resource-id"
    }
  ]
}
```

| 字段 | 必选 | 类型 | 调用约定 |
| --- | --- | --- | --- |
| `query` | 否 | string | 当前这一轮的用户请求。推荐场景下建议传入非空文本；不要把历史对话拼接到该字段。|
| `draftAnswer` | 否 | string | 当前轮已有的回答草稿或最新助手回复。|
| `history` | 否 | array | 既往交互，按发生时间从早到晚传入。缺省时按空数组处理。|
| `history[].role` | 否 | string | 发言角色。推荐使用 `user`、`student`、`assistant`、`teacher`。|
| `history[].content` | 否 | string | 对话文本。也可使用 `text`、`query` 或 `draftAnswer` 代替。|
| `history[].resourceId` | 否 | string | 已与学习者发生交互的资源 ID。资源推荐场景可传入多个。|
| `history[].userId` | 否 | string | 已与学习者发生交互的用户 ID。学伴推荐场景可传入多个。|

`history` 中的条目可以只传 `resourceId` 或 `userId`，无需同时附带对话文本。重复的资源 ID 和用户 ID 会按首次出现顺序去重。

### 4.4 `userContext`

以下字段均为必选非空字符串：

```json
{
  "stage": "seniorHighSchool",
  "grade": "grade10",
  "subject": "physics",
  "learnerStateSummary": "牛顿运动定律掌握不足"
}
```

| 字段 | 说明 |
| --- | --- |
| `stage` | 学习阶段，例如 `primarySchool`、`juniorHighSchool`、`seniorHighSchool`。|
| `grade` | 年级标识，例如 `grade5`、`grade10`。|
| `subject` | 当前学科，例如 `physics`、`math`。|
| `learnerStateSummary` | 调用方已有的学情摘要。|

### 4.5 `learningEvidence`

至少传入一条学习证据：

```json
[
  {
    "knowledgePointId": "kp-phys-newton-laws-003",
    "responseResult": "incorrect",
    "occurredAt": "2026-09-14T09:00:00Z"
  }
]
```

| 字段 | 必选 | 类型 | 说明 |
| --- | --- | --- | --- |
| `knowledgePointId` | 是 | string | 知识点 ID。建议传入服务侧可识别的 ID。|
| `responseResult` | 是 | string | 作答或学习结果，例如 `correct`、`incorrect`、`partial`。|
| `occurredAt` | 是 | string | 发生时间，建议使用 ISO 8601 UTC 时间格式，例如 `2026-09-14T09:00:00Z`。|

可以在每条证据中增加调用方自有扩展字段，当前版本不会要求固定字段以外的数据。

## 5. 资源推荐

资源推荐使用：

```json
"scenarioCode": "resourceRecommendation"
```

### 5.1 自主推荐

不传 `candidateResources`，或传入空数组时，服务会根据当前请求、对话上下文和学习证据给出资源推荐。

### 5.2 指定候选资源排序

传入非空 `candidateResources` 时，服务只对该列表中的有效资源进行排序，最多返回 5 条。

```json
"candidateResources": [
  {
    "resourceId": "resource-id-1"
  },
  {
    "resourceId": "resource-id-2"
  }
]
```

| 字段 | 必选 | 类型 | 说明 |
| --- | --- | --- | --- |
| `candidateResources` | 否 | array | 候选资源列表。非空时启用指定候选排序。|
| `candidateResources[].resourceId` | 是 | string | 候选资源 ID。|

同一资源 ID 重复传入时只保留第一次。若列表中存在不可识别的资源 ID，本次请求返回 `400001`，不会返回部分结果。

### 5.3 资源推荐请求示例

```json
{
  "processingStage": "learningSupport",
  "data": {
    "scenarioCode": "resourceRecommendation",
    "interactionContext": {
      "query": "请推荐两个适合复习牛顿运动定律的资源",
      "history": [
        {
          "role": "user",
          "content": "我之前看过基础讲解，还是不会受力分析。"
        }
      ]
    },
    "userContext": {
      "stage": "seniorHighSchool",
      "grade": "grade10",
      "subject": "physics",
      "learnerStateSummary": "牛顿运动定律掌握不足"
    },
    "learningEvidence": [
      {
        "knowledgePointId": "kp-phys-newton-laws-003",
        "responseResult": "incorrect",
        "occurredAt": "2026-09-14T09:00:00Z"
      }
    ]
  }
}
```

## 6. 学伴推荐

学伴推荐使用：

```json
"scenarioCode": "studyBuddyRecommendation"
```

### 6.1 自主推荐

不传 `candidateUsers`，或传入空数组时，服务会基于当前请求、对话上下文和学习证据推荐可用学伴，最多返回 5 位。

### 6.2 指定候选学伴排序

`candidateUsers` 是学习支持推荐的扩展字段。传入非空数组时，服务只对其中的有效用户进行排序。

```json
"candidateUsers": [
  {
    "userId": "user-id-1"
  },
  {
    "userId": "user-id-2"
  }
]
```

| 字段 | 必选 | 类型 | 说明 |
| --- | --- | --- | --- |
| `candidateUsers` | 否 | array | 候选学伴用户列表。非空时启用指定候选排序。|
| `candidateUsers[].userId` | 是 | string | 候选学习者的用户 ID。|

同一用户 ID 重复传入时只保留第一次。调用方自身不会作为推荐对象返回；不满足推荐条件的候选用户也可能不出现在结果中。若候选列表含不存在或不可用的用户 ID，本次请求返回 `400001`，不会返回部分结果。

### 6.3 学伴推荐请求示例

```json
{
  "processingStage": "learningSupport",
  "data": {
    "scenarioCode": "studyBuddyRecommendation",
    "interactionContext": {
      "query": "请从候选用户中推荐两位一起复习牛顿运动定律的学伴",
      "history": [
        {
          "role": "user",
          "content": "我希望找愿意一起讨论受力分析的同学。"
        },
        {
          "userId": "previous-buddy-user-id"
        }
      ]
    },
    "userContext": {
      "stage": "seniorHighSchool",
      "grade": "grade10",
      "subject": "physics",
      "learnerStateSummary": "牛顿运动定律掌握不足"
    },
    "learningEvidence": [
      {
        "knowledgePointId": "kp-phys-newton-laws-003",
        "responseResult": "incorrect",
        "occurredAt": "2026-09-14T09:00:00Z"
      }
    ],
    "candidateUsers": [
      {
        "userId": "candidate-user-id-1"
      },
      {
        "userId": "candidate-user-id-2"
      }
    ]
  }
}
```

## 7. 成功响应

### 7.1 统一响应信封

```json
{
  "code": "000000",
  "message": "success",
  "requestId": "调用方传入的requestId",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | string | 业务返回码。`000000` 表示请求已被正常处理，包括带降级标记的可用结果。|
| `message` | string | 返回码对应说明。|
| `requestId` | string | 与请求头中的 `requestId` 一致。|
| `data` | object | 推荐结果或错误附加数据。|

### 7.2 资源推荐结果

```json
{
  "code": "000000",
  "message": "success",
  "requestId": "req-resource-001",
  "data": {
    "decision": {
      "action": "pass",
      "reason": "已完成推荐排序。"
    },
    "learnerState": {
      "masterySummary": "牛顿运动定律掌握不足"
    },
    "recommendations": [
      {
        "resourceId": "resource-id-1",
        "reason": "基于当前学习证据和交互上下文完成排序。"
      }
    ],
    "trace": {
      "traceId": "服务生成的追踪ID",
      "capabilityVersion": "版本号",
      "processedAt": "2026-09-14T09:00:01.000000+00:00"
    }
  }
}
```

### 7.3 学伴推荐结果

学伴推荐的通用 `recommendations` 固定为空数组，学伴结果放在扩展对象 `ext.studyBuddyRecommendation.buddies` 中。

```json
{
  "code": "000000",
  "message": "success",
  "requestId": "req-buddy-001",
  "data": {
    "decision": {
      "action": "pass",
      "reason": "已完成推荐排序。"
    },
    "learnerState": {
      "masterySummary": "牛顿运动定律掌握不足"
    },
    "recommendations": [],
    "ext": {
      "studyBuddyRecommendation": {
        "buddies": [
          {
            "userId": "candidate-user-id-1",
            "nickname": "学习伙伴",
            "matchScore": 0.91,
            "reason": "基于当前学习证据和交互上下文完成排序。"
          }
        ]
      }
    },
    "trace": {
      "traceId": "服务生成的追踪ID",
      "capabilityVersion": "版本号",
      "processedAt": "2026-09-14T09:00:01.000000+00:00"
    }
  }
}
```

| 学伴字段 | 类型 | 说明 |
| --- | --- | --- |
| `userId` | string | 推荐学伴的用户 ID。|
| `nickname` | string | 推荐学伴显示名称。|
| `matchScore` | number or null | 匹配分数。无可用分数时可为 `null`。|
| `reason` | string | 推荐理由。|

## 8. 降级响应

当接口已完成请求处理但只能返回降级结果时，仍返回：

```json
"code": "000000"
```

同时会在 `data` 中增加：

```json
{
  "degraded": true,
  "degradeReason": "graphRankingUnavailable",
  "availableResults": ["可用资源或用户ID"]
}
```

调用方应展示或记录 `degraded` 状态，并可使用 `availableResults` 作为当前可返回结果的 ID 列表。`availableResults` 可能为空。

## 9. 错误码

| `code` | 含义 | 典型原因 | 调用方处理建议 |
| --- | --- | --- | --- |
| `000000` | 成功 | 请求已处理；可能带有 `degraded=true`。 | 读取 `data`，并额外检查是否降级。|
| `200001` | 缺少必填字段 | 缺少公共请求头、`processingStage`、`data`、`scenarioCode`、`userContext`、学习证据必要字段等。 | 补齐 `message` 指出的字段后重试。|
| `200002` | 字段值或类型不合法 | `apiVersion` 非 `v1`、场景码不支持、对象/数组类型错误、必填文本为空等。 | 按字段约束修正请求后重试。|
| `400001` | 候选对象不可用 | 指定候选资源不存在，或指定候选用户不存在/不可用。 | 刷新候选列表后重试；不要期待返回部分候选结果。|
| `500001` | 接口限流 | 当前调用频率超过限制。 | 根据 `data.retryAfterMs` 延迟重试。|
| `900000` | 服务内部异常 | 未预期的服务端错误。 | 保留 `requestId` 并联系接口维护方定位。|


## 11. 调用注意事项

1. `requestId` 应在每次请求中保持唯一，便于双方联调和问题定位。
2. `query` 只放本轮当前诉求；既往消息放入 `history`，并保持时间顺序。
3. `candidateResources` 与 `candidateUsers` 分别对应两种场景，不建议交叉传递。
4. 候选列表为非空时，返回结果仅来自该候选列表；候选列表为空时等同于未传候选列表。
5. 推荐结果最多返回 5 条。调用方应允许结果少于请求文本中的数量，因为有效候选数量可能不足。
6. 当 `code` 为 `000000` 且 `data.degraded=true` 时，调用方可展示已有结果，同时记录 `degradeReason` 和 `requestId`。
7. 请求和响应均使用 UTF-8 JSON 编码。
